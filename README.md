# Лабораторная работа № 4
## Тема проекта: Космос и астрофизика 13 (Экзопланеты и телескопы)

**Цель работы:** завершение бэкенда для SPA.

**Задание:** добавить аутентификацию, авторизацию и Swagger в веб-сервис, подготовить ТЗ. В Go-бэкенде регистрация и вход работают через API; при входе сервер выдаёт JWT, а при выходе отзывает его через blacklist в Redis. При создании карточки ID создателя берётся из проверенного токена.

Список телескопов и лента доступны гостям. Просмотр своего черновика, создание, публикация, удаление и лайки требуют авторизации. Регистрация и вход доступны без токена. В Swagger защищённые операции отмечены замком; сервер проверяет доступ независимо от клиента.

**Порядок показа:**

- **Скриншоты 1–3.** В Swagger в режиме инкогнито выполнить вход и получить список телескопов. Взять JWT из поля `access_token` и использовать его в Insomnia или Postman в заголовке `Authorization: Bearer <токен>`.
- **Скриншоты 4–5.** В Insomnia или Postman выполнить `GET /api/telescopes` без токена и с токеном. Список доступен в обоих случаях.
- **Скриншоты 6–8.** Выполнить `PUT /api/telescopes/:id` для своего черновика: без токена получить `401`, с токеном владельца — `200` и обновлённую карточку. После выхода показать запись отозванного токена в Redis через `redis-cli`.
- **Скриншот 9.** В StarUML показать, что свойство `signature` у сообщений переиспользует методы диаграммы классов.

**Контрольные вопросы:** cookies, сессии, Redis, JWT, аутентификация и авторизация, SSO, двухфакторная аутентификация, RSA.

**Диаграмма последовательности:** показать HTTP-запросы бизнес-процесса без линий БД и нативного приложения: вход, получение списка с фильтром, создание карточки с изображением и видео, получение черновика, публикация, получение первой карточки ленты без ID, переход к следующей карточке через `?id=…&next=true` и постановка лайка. Домены оформить как `Lifeline`, для сообщений выбирать методы из диаграммы классов, ключевые входные и выходные данные указывать в `arguments` у `Message`.

## Описание REST API методов

### Домен телескоп

| # Метода | Название HTTP метода | URL эндпоинт | Тело запроса | HTTP код | Описание |
| --- | --- | --- | --- | --- | --- |
| 1 | GET | `/api/telescopes?min=-90&max=90` | — | 200 OK | Список опубликованных телескопов с фильтром широты. |
| 2 | GET | `/api/telescopes/feed?id=1&next=true` | — | 200 OK | Получение первой, указанной или следующей карточки ленты. |
| 3 | GET | `/api/telescopes/draft` | — | 200 OK | Получение черновика текущего пользователя. |
| 4 | POST | `/api/telescopes` | `multipart/form-data`: `title`; необязательные файлы `image`, `video` | 201 Created | Создание черновика с загрузкой медиа в MinIO. |
| 5 | PUT | `/api/telescopes/:id` | JSON: `{"description":"Описание телескопа","latitude":38.5,"longitude":12.4}` | 200 OK | Публикация своего черновика. |
| 6 | DELETE | `/api/telescopes/:id` | — | 200 OK | Логическое удаление своей карточки. |
| 7 | POST | `/api/telescopes/:id/likes` | JSON: `{"like":1}` или `{"like":0}` | 200 OK | Установка или отмена лайка текущего пользователя. |

Параметры `min`, `max`, `id` и `next` передаются в URL и необязательны; `next` используется только вместе с `id`. Без `id` лента возвращает первую карточку, с `id` — указанную, с `id` и `next=true` — следующую.

### Авторизация и Swagger

Список телескопов и лента доступны гостю. Для черновика, создания, публикации, удаления, лайков и выхода нужен заголовок `Authorization: Bearer <токен>` с ролью создателя. Вход и регистрация доступны без токена. Владелец карточки определяется по `user_id` из JWT.

Добавьте в `app/.env` переменную `JWT_SECRET` со случайным секретом длиной не менее 32 байт. Redis по умолчанию доступен на `127.0.0.1:6379`; для другого подключения задайте `REDIS_HOST`, `REDIS_PORT` и при необходимости `REDIS_USER`, `REDIS_PASSWORD`.

Запуск Redis из папки `app`: `docker compose -f compose.redis.yml up -d`. В Swagger по адресу `/swagger/index.html` выполните вход и в **Authorize** вставьте `Bearer <access_token>`.

Обновление Swagger из аннотаций (из папки `app`):

```powershell
swag init -g cmd/app/main.go --parseInternal
```
